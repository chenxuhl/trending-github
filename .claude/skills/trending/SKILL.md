# trending 抓取与中文报告

## 步骤

1. 跑脚本：
   ```bash
   node trending.mjs
   ```
   输出 `report.md`（底稿：种子信号 + 日/周/月/季/年五榜）+ 更新 `history.json`。star 数异常（全相同/过小）→ GitHub 改版，跑 `node trending.mjs --selftest` 修 `parseTrending` 正则。

2. 读 `report.md`。**先看第一节「🆕 本期新增」**——脚本已自动 diff 上期（`seen.json`），跨榜列出所有新项目。这节是报告的核心内容来源。其余各榜用于补充上下文。
   - 种子信号（`seeds.json` 作者新 repo + topic 新项目；脚本已收紧：仅「近 90 天新建」或「命中方向标签」的项目）
   - 日榜 / 周榜（trending）
   - 🔥 持续在榜 ≥4 期
   - 月榜（trending）/ 季榜、年榜（Search API 新建 + star 排序）

3. 写 `report-zh.md`（覆盖式，每期一份，**结构 = 精华 + 全量备查**）：
   - 全文中文，repo 名/链接保留原文
   - **💎 精华节（报告开头，10±3 个）**：**直接用底稿第一节「💎 精华候选」的脚本排序**（价值分已算好：强标签 + 赚钱类加权 + 强词密度 + 早期窗口 + 增速 − 大热降权 − 在榜衰减 − 无描述/0星扣分，镜像类硬排除）。只做两件事：①翻译 + 写「为什么是精华」和「你怎么用」两列 ②分数明显不合理时人工调序并说明理由。**不要自己从零重新挑**——脚本的 `score()` 是筛选标准的权威实现。
   - **淘汰说明必写**：按「弱词降级 / 大热降权 / 在榜衰减 / 方向不符 / 镜像构建产物 / 0星」分类说明，各举 2-3 个实例。用户要看到筛选有依据。
   - **全量节（精华之后，标「备查」）**：种子信号合并成**一节**（不按作者/topic 拆两节），方向命中优先排，方向无关/低信息量（无描述、纯构建版、镜像）压成一句话带过行；其余各榜全部条目表格化（项目/星数/增量或建于/标签/一句话），供检索不供通读
   - 「本期新增」有值时在精华节前加一段（新增的是精华首选来源）
   - 标签判断优先读描述人工归类（正则 `INTERESTS` 只是粗筛，中文项目正则漏标时人工补）
   - 种子清单维护：用户提到在用/关注新工具时，建议加进 `seeds.json`
   - **不要**把五榜折叠成「相关/无关」两层——用户试过并否决了那种格式
   - **不要啰嗦**——用户反馈过三次报告问题（太啰嗦×2、筛选不精华×1）。精华节每条自问：不行动用户损失什么？全量节每行只保底信息。同一项目精华节和全量节都出现是允许的（一处详一处略）。

4. 回复用户：3-5 行摘要，点名本期最值得看的 2-3 个项目及理由（按用户两个方向评估价值），并附 `report-zh.md` 路径。

## 用户偏好（执行时遵守）

- 中文阅读优先，任何报告/摘要必须中文。
- 两个关注方向：①能提效工作 ②能赚钱——赚钱细分为三个维度：💰 副业（做产品/服务变现）、💼 求职（面试/简历/职业）、📈 投资（交易/量化/加密）。评估项目价值只从这些角度。
- 讨厌信息滞后：持续热门项目必须显式标出在榜期数。
- star 数、增量数字必须准确，不臆造。

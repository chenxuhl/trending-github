# trending 抓取与中文报告

## 步骤

1. 跑脚本：
   ```bash
   node trending.mjs
   ```
   输出 `report.md`（底稿：种子信号 + 日/周/月/季/年五榜）+ 更新 `history.json`。star 数异常（全相同/过小）→ GitHub 改版，跑 `node trending.mjs --selftest` 修 `parseTrending` 正则。

2. 读 `report.md`。**先看第一节「🫰 早期机会」**——这是用户的核心诉求：赚钱门路的窗口期在项目 2~8 周、星数还低（30~3000）、日均涨星正在起飞时。这节按增速排序，是报告的第一主角。其次「💎 精华候选」和「🆕 本期新增」。
   - 🫰 早期机会（60 天内新建 + 钱💰💼📈命中 + 质量闸门，按日均涨星排序）
   - 💎 精华候选 / 🆕 本期新增
   - 种子信号 / 日榜 / 周榜 / 🔥 持续在榜 / 月榜 / 季榜 / 年榜（备查）

3. 写 `report-zh.md`（覆盖式，每期一份，**结构 = 早期机会 + 精华 + 全量备查**）：
   - 全文中文，repo 名/链接保留原文
   - **🫰 早期机会节（报告开头，主角）**：逐条给四列——「这是什么风口 / 验证方式（具体到动作：落地页+投放渠道+预算）/ 最快变现路径（按收益速度序：卖服务→模板→micro-SaaS）/ 窗口判断」。用户的变现方法论（2026-11-25 确认）：
     - **好 idea 判据（四条同时成立）**：真实付费痛（有人已在花钱解决）+ 一周内能触达 100 个买家 + 不公平优势（别人 3 月你 3 天）+ 验证成本 <500 元一个周末。缺任何一条降级到备查。
     - **验证顺序（先卖再做）**：落地页带价格 → 投痛点人群 100-300 元 → 数付费按钮点击率（≥3% 可行）/ 留联系方式数 / 聊 5 个人。聊天发现替代方案是「不做」= 死。
     - **变现速度序（从上往下选）**：卖服务（0-2 周，99-299 试水）→ 卖模板（2-4 周，Gumroad/面包多）→ micro-SaaS（服务跑通 10 单后产品化收月费）→ 内容型（最慢，复利）。
     - 每周投入 >10 小时的 idea 不做（用户有正职）。
     - 增速数字（日均 +N 星）必须保留——窗口期量化指标。
   - **💎 精华节（报告开头，10±3 个）**：**直接用底稿第一节「💎 精华候选」的脚本排序**（价值分已算好：强标签 + 赚钱类加权 + 强词密度 + 早期窗口 + 增速 − 大热降权 − 在榜衰减 − 无描述/0星扣分，镜像类硬排除）。只做两件事：①翻译 + 写「为什么是精华」和「你怎么用」两列 ②分数明显不合理时人工调序并说明理由。**不要自己从零重新挑**——脚本的 `score()` 是筛选标准的权威实现。
   - **淘汰说明必写**：按「弱词降级 / 大热降权 / 在榜衰减 / 方向不符 / 镜像构建产物 / 0星」分类说明，各举 2-3 个实例。用户要看到筛选有依据。
   - **全量节（精华之后，标「备查」）**：种子信号合并成**一节**（不按作者/topic 拆两节），方向命中优先排，方向无关/低信息量（无描述、纯构建版、镜像）压成一句话带过行；日/周/月榜可压成紧凑一行式；**季榜和年榜必须表格全量保留（项目链接/星数/建于/标签/一句话），禁止压成一段文字**——用户明确要求（2026-11-25）：「一定要把季度榜单和年度榜单保留，这样我才不会遗漏很多有价值的开源项目」
   - 「本期新增」有值时在精华节前加一段（新增的是精华首选来源）
   - 标签判断优先读描述人工归类（正则 `INTERESTS` 只是粗筛，中文项目正则漏标时人工补）
   - 种子清单维护：用户提到在用/关注新工具时，建议加进 `seeds.json`
   - **不要**把五榜折叠成「相关/无关」两层——用户试过并否决了那种格式
   - **不要啰嗦**——用户反馈过三次报告问题（太啰嗦×2、筛选不精华×1）。精华节每条自问：不行动用户损失什么？全量节每行只保底信息。同一项目精华节和全量节都出现是允许的（一处详一处略）。

4. 回复用户：3-5 行摘要，点名本期最值得看的 2-3 个项目及理由（按用户两个方向评估价值），并附 `report-zh.md` 路径。

## 用户偏好（执行时遵守）

- 中文阅读优先，任何报告/摘要必须中文。
- **核心目标：赚更多钱**（2026-11-25 升级为首要目标）。两个方向：①能提效工作 ②能赚钱——赚钱细分为：💰 副业、💼 求职、📈 投资。评估项目价值只从这些角度，按「能不能直接变现」排优先级。
- 讨厌信息滞后：持续热门项目必须显式标出在榜期数。
- star 数、增量数字必须准确，不臆造。

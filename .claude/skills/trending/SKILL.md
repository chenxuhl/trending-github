# trending 抓取与中文报告

## 步骤

1. 跑脚本：
   ```bash
   node trending.mjs
   ```
   输出 `report.md`（底稿：种子信号 + 日/周/月/季/年五榜）+ 更新 `history.json`。star 数异常（全相同/过小）→ GitHub 改版，跑 `node trending.mjs --selftest` 修 `parseTrending` 正则。

2. 读 `report.md`。结构（照搬到底稿顺序）：
   - 种子信号（`seeds.json` 作者新 repo + topic 新项目；脚本已收紧：仅「近 90 天新建」或「命中方向标签」的项目）
   - 日榜 / 周榜（trending）
   - 🔥 持续在榜 ≥4 期
   - 月榜（trending）/ 季榜、年榜（Search API 新建 + star 排序）

3. 写 `report-zh.md`（覆盖式，每期一份，**目标 ≤80 行**）：
   - 全文中文，repo 名/链接保留原文
   - **结构**：选择策略（2-3 行）→ 与上期变化（1-2 行）→ 「只看这里就够的 3 个项目」表（唯一展开区，给「对你的用处」）→ 种子信号 → 日榜 → 周榜 → 月榜 → 季榜 → 年榜
   - **去重铁律**：一个项目全文只展开一次。进了开头 3 项目表的，正文各榜只留名字；上期报告已展开过的项目，本期不再展开（只列名字）。每期都重复的周榜常驻项目尤其要压。
   - 各榜小节规则：新面孔（上期没有的）+ 方向命中项给一行「星数 | 标签 | 一句话」；其余合并成「带过」一行（名字+星数），带过行总数 ≤10 项，超了就砍最不相关的。
   - 「值得看」≠ 遍历：每榜只挑真正方向强对口的（通常 2-5 个），弱相关高星项目归带过。
   - 表格最多 4 列（项目/星数/标签/一句话），增量信息并入星数列。
   - 持续在榜期数只在「与上期变化」提：全榜常驻无变化时一句话（如「周榜 13 个全部在榜 18 期，无新面孔」），不重列整表。
   - 标签判断优先读描述人工归类（正则 `INTERESTS` 只是粗筛，中文项目正则漏标时人工补）。
   - 种子清单维护：用户提到在用/关注新工具时，建议加进 `seeds.json`。
   - **不要**把五榜折叠成「相关/无关」两层——用户试过并否决了那种格式。
   - **不要啰嗦**——用户反馈过报告太啰嗦。每句话自问：删掉这行用户损失什么信息？答案是「无」就删。

4. 回复用户：3-5 行摘要，点名本期最值得看的 2-3 个项目及理由（按用户两个方向评估价值），并附 `report-zh.md` 路径。

## 用户偏好（执行时遵守）

- 中文阅读优先，任何报告/摘要必须中文。
- 两个关注方向：①能提效工作 ②能赚钱——赚钱细分为三个维度：💰 副业（做产品/服务变现）、💼 求职（面试/简历/职业）、📈 投资（交易/量化/加密）。评估项目价值只从这些角度。
- 讨厌信息滞后：持续热门项目必须显式标出在榜期数。
- star 数、增量数字必须准确，不臆造。
